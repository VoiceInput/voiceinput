## Observed failures and rechecks

- The version PR's first CI attempt lost its local Wrangler server after 62
  website checks. Four WebKit tests then failed to connect.
  [The complete rerun](https://github.com/VoiceInput/voiceinput/actions/runs/34887009315/attempts/2)
  passed without source changes. The final main candidate passed its own
  complete CI run.
- [The first provider workflow](https://github.com/VoiceInput/voiceinput/actions/runs/34888842369)
  passed all protocol checks and the OpenAI and Deepgram browser sessions, but
  its ElevenLabs browser check failed after 30.1 seconds. The sanitized reporter
  classified this as an application check failure without retaining a detailed
  cause. A focused local ElevenLabs run passed in 18.8 seconds, and the fresh
  full provider workflow passed all providers without source changes. The
  original failure remains recorded; no check was waived.

## Testing release retirement

The owner identified every earlier beta as an unused testing build and requested
its removal on September 14, 2026. Both GitHub beta releases and the
`v0.1.0-beta.1` and `v0.1.0-beta.2` tags were removed. The stable `v0.1.0`
release, its candidate tag, and its evidence assets remain published. Historical
records below describe testing work; they do not establish a beta compatibility
policy.

The registry was rechecked after the website redeployment: `latest` and `next`
still resolve to `0.1.0` for all six packages, and all stable tarball hashes and
provenance attestations match the approved release. Both React betas, both
OpenAI betas, and ElevenLabs `0.1.0-beta.1` were removed from npm with owner
passkey confirmation. The owner then stopped further beta removal and clarified
that the requirement is for ordinary installs to receive the current stable
release. The pending unpublish command was canceled. A fresh registry check
confirmed `latest` and `next` still point to `0.1.0` for all six packages;
remaining historical beta versions do not affect ordinary installs.

## Generated release notes

The following entries are copied from the generated package changelogs.
References to prereleases describe historical testing changes accumulated before
0.1.0. Those builds had no external users and impose no backward compatibility
or migration requirements. The public GitHub release describes the initial API.

### @voiceinput/provider

#### Minor Changes

- a290175: Prepare the package APIs for 0.1.0. Token handlers now use shared
  types from `@voiceinput/provider`:

  - `OpenAIAuthorization`, `ElevenLabsAuthorization`, and
    `DeepgramAuthorization` → `VoiceTokenAuthorization`
  - `OpenAIRateLimitResult`, `ElevenLabsRateLimitResult`, and
    `DeepgramRateLimitResult` → `VoiceTokenRateLimitResult`
  - `OpenAITokenHandlerContext`, `ElevenLabsTokenHandlerContext`, and
    `DeepgramTokenHandlerContext` → `VoiceTokenHandlerContext`

  Rename the OpenAI `clientSecretUrl`, ElevenLabs `tokenUrl`, and Deepgram
  `grantUrl` handler options to `providerTokenUrl`. Deepgram token callback
  metadata now reports `expiresAt` in epoch milliseconds instead of `expiresIn`
  seconds, matching OpenAI. OpenAI callback metadata also normalizes its
  upstream seconds value to epoch milliseconds.

  React trigger bindings move from `triggerProps` → `getTriggerProps()`. React
  also re-exports the core text snapshot, target, selection, span, audio source,
  transcript transform, interim behavior, and error code types used by React
  consumers.

- 604dca7: Prepare the fixed VoiceInput package suite for its initial `0.x`
  prerelease.
- 5523385: Make the built-in AudioWorklet safe under consumer bundling and
  report blocked browser audio activation separately from microphone permission
  denial.

  Preserve visible dictation when graceful shutdown times out, expose a
  configurable finalization deadline and background-recording policy, and
  improve initial React support detection, field writability subscriptions, and
  prefilled-field selection.

  Provide a stable user-facing error-message helper, retain upstream diagnostics
  in error causes, and clarify provider defaults, accessibility, and release
  channels.

  Preserve visible text when finalization fails as well as when it times out.
  The new `user-activation-required` error code requires updating exhaustive
  switches over `VoiceInputErrorCode`.

#### Patch Changes

- 6182fee: Prepare the documented desktop beta with segment-aware editing,
  field-local undo/redo, grapheme-safe maxLength enforcement, composition
  protection, and safe disabled/read-only/reset behavior. VoiceTextarea and
  VoiceInput now notify one onValueChange callback for typing and voice edits,
  including undo/redo; uncontrolled React onChange also receives dictation.
  Recording configuration is sampled at Start so inline provider factories do
  not interrupt recording.

  Capture buffers up to 15 seconds while connecting, provider sends have bounded
  congestion deadlines, and backgrounding and audio interruptions clean up
  resources. New public APIs include segmentId, undo(), redo(), onTextLimit and
  the max-length, target-unavailable and backgrounded stop reasons. OpenAI now
  defaults to gpt-transcribe with 500 ms server VAD: the live model remains
  opt-in for one manual-commit segment per recording.

  See docs/editing-contract.md and docs/form-integration.md for migration and
  integration details. Automated desktop engine coverage, installed React 18/19
  consumers and the no-account simulated example accompany this beta; physical
  mobile and manual assistive-technology verification remain pending.
