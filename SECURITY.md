# Security policy

## Supported versions

Before the first stable release, only the newest prerelease on the npm `next`
tag receives security fixes. Once stable releases begin, the
[support policy](docs/support-policy.md) will list every maintained release
line.

## Report a vulnerability privately

Do not open a public issue. Use GitHub's
[private vulnerability report](https://github.com/VoiceInput/voiceinput/security/advisories/new)
to share reproduction steps, affected versions, impact, and any suggested
mitigation. This creates a private discussion with the maintainers and supports
coordinated disclosure and credit.

Never include real provider keys, issued credentials, microphone recordings, or
user transcripts. Use redacted values or a minimal test account.

The maintainers will acknowledge the report, investigate it, and coordinate a
fix and disclosure timeline through the private advisory. Please avoid public
disclosure until a fix is available or a disclosure date has been agreed.
